## Summary
Documents the [[server-api-app|`app.*` server API]] a process can call. Categories:
- **Database CRUD** — direct MongoDB, **bypasses sdform permissions**: `dbInsert(Many)`, `dbFindAll/One/ById`, `dbUpdate(Many)`, `dbDelete(Many)`, `dbObjectId`, `curDate`, raw `db`/`mongoClient`. Auto audit fields (`created_by/at`, `updated_by/at`). Queries use the [[dataprovider|SdDataProvider]] shape and support raw NoSQL `aggregate` pipelines.
- **SDForm functions** — go **through** sdform (permissions + events): `sdformGetOne/GetAll/SetOne/DelOne`. `sdformDelOne` is a **soft delete** (`xrstatx = 3`).
- **Form Management** — `initSaveForm` (creates empty record, `xrstatx = 0`), `insertData(Form)`, `createJoinerValue`, `updateFileStatus`, `deleteFileSystem`, `dataPolicyAudit`, `afterSaveForm`/`afterDeleteForm` events.

- **[[xformdatax]]** — the special return key that merges values back into the just-saved form document.
- **SQL & Query** — `runSql` (call a [[sql-factory|SQL Factory]] query), `parsedSQL`, `parsedProvider`, `pgQuery` (Postgres).

## Key takeaways
- **Two access tiers:** `app.db*` hits [[mongodb|MongoDB]] directly (fast, no permission/event checks) vs `app.sdform*` which enforces the form's permissions and fires its events. Choosing between them is a real design decision.
- **[[zdata-collections|`zdata_*` collections]]** are the data store; records carry a status field **`xrstatx`** and audit fields.
- Queries everywhere share one object shape — the [[dataprovider|SdDataProvider]] (`from`, `select`, `where` with `:params`, `orderBy`, `limit/page`, or raw `nosql`).
- [[xformdatax]] is the **only** channel to push computed values back into a form after save, and it only fires from a `form_event`-bound call.

## Contradictions / open questions
- **`xrstatx` status codes:** `sdformSetOne` documents `rstat` as `0=draft, 1=active, 2=submitted, 3=deleted`, and soft-delete sets `xrstatx = 3`; `initSaveForm` creates records at `xrstatx = 0`. But the client-side `submitForm` (see [[llm-field-docs]]) uses a **different** numbering (`1=draft, 2=submit`). Tracked in [[zdata-collections]].
- **`xrstatx` type:** examples use both numeric (`{ $nin: [0,3] }`) and **string** (`{ xrstatx: '1' }`) — unresolved whether the field is stored as number or string. Flagged in [[zdata-collections]].
