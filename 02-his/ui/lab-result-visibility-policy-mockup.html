ตารางตัดสินใจที่เสนอ

LAB hold ตรงกับ revision ปัจจุบันSensitive จาก CPOE masterLAB เห็นค่าEMR เห็นค่าการทำงานของเจ้าหน้าที่
ไม่ไม่เห็นเห็นทันทีไม่มีงานเพิ่ม
ใช่ไม่เห็นไม่เห็น · แจ้งกำลังตรวจสอบกด “พักเผยแพร่” 1 ครั้ง; callback revision ใหม่เปิดเอง
ไม่ใช่เห็นยืนยันตัวตนก่อนดูLAB ไม่ต้องทำอะไรเพิ่ม
ใช่ใช่เห็นไม่เห็น แม้ re-auth แล้วรอผลใหม่/ยกเลิกพัก; จากนั้น EMR จึง re-auth

Contract เชื่อม LAB กับ EMR/CPOE

  1. Snapshot policy ตอนสั่งตรวจอ่าน flag เดิม pick_master.is_hide_result แล้ว normalize เป็น sensitive=true; ห้ามให้ LAB เปลี่ยน policy นี้
  2. เก็บประวัติเป็นผลทั้งก้อนทุก accepted callback สร้าง immutable row ใน zdata_lab_result_revision_log แล้วจึงอัปเดต current Result Items ใน transaction เดียวกัน
  3. พักเผยแพร่ต้องผูก revisionเก็บ held_revision_id + เหตุผล/ผู้ทำ/เวลาแยกจาก immutable log; effective hold เมื่อเท่ากับ active_revision_id เท่านั้น
  4. EMR รับ state ก่อนรับค่าAPI คืน withheld, reauth_required หรือ visible; กรณีล็อกห้ามส่ง raw value มาแค่ซ่อนด้วย CSS
  5. Re-auth ผ่าน API กลางserver ตรวจรหัสผ่านและออก grant อายุสั้น ผูก user + patient + order + revision พร้อม audit การเปิดดู
