Remark สำหรับยืนยันกับ Agent / API

  • Agent/API ระบุสถานะครบระดับ test และรายการ result component ที่จำเป็น หน้า UI จะแสดงค่าตาม contract และไม่อนุมานเองว่า test ที่มีหลาย result ออกผลครบแล้วหรือยัง
  • รองรับการรับหรือปฏิเสธแยกระดับ test ภายใน order เดียว: test ที่ปฏิเสธต้องคงอยู่เป็น log ใต้ order แต่ไม่นำมานับเป็นรายการรอผล; เมื่อ test ที่รับไว้ออกผลครบ order จึงเป็น `ออกผลครบ`
  • ขอบเขต Worklist มาจาก `organization_id`, `lab_section_ids` และสิทธิ์ของผู้ใช้ที่ login โดย Agent/API ต้องตรวจสิทธิ์ซ้ำทุก request; หน้า UI ไม่มีตัวเลือกห้องแลปให้ผู้ใช้เลือกเอง
  • Test Master กำหนด `result_entry_mode = machine | manual | fallback`, `result_schema_id`, `unit_id` และ `requires_verification` แล้ว snapshot ค่าไว้ที่ Order Item เพื่อไม่ให้การแก้ Master ภายหลังเปลี่ยนรายการเก่า
  • เวลาเก็บ specimen ที่ว่างไม่บล็อกการรับ: UI ยังแสดง “–” และบันทึกเวลารับจริง โดยพักการส่ง Agent ไว้ที่ `awaiting_collection` จนต้นทางส่งเวลาเก็บจริงมา
  • หน้า order ไม่มีคอลัมน์ผลตรวจ; หน้าออกผลแสดง `ดูผล` รอไว้ทุก Item และเปิด popup ได้ก่อนมีผล ปุ่มดินสอเริ่มกรอกผล/Unit/แปลผล/ค่าปกติได้หลังรับ specimen ส่วนค่าก่อนหน้าเป็น audit ระดับ Item และแก้ไขไม่ได้
  • ฟอร์มอ้างอิง `lab_reject.json` ปัจจุบันเป็น logic ของ Lab CHE; งานจริงต้องเลือก master เหตุผลตาม `lab_section` และบันทึกผู้ปฏิเสธจาก runtime user context
