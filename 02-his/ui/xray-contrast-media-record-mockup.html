หมายเหตุการนำไป implement

  • หน้านี้เป็น mockup ข้อมูลสมมติทั้งหมด — HN ชื่อผู้ป่วย แพทย์ เลข Order/Accession ยี่ห้อสารทึบ Lot และเวลา ห้าม hard-code ลงระบบจริง
  • โครงหน้าทั้งหมด (toolbar · แถวผู้ป่วย · แผงรายละเอียด) ยกจาก X-ray CPOE Worklist — CSS และ markup คัดลอกตรงจาก 02-his/ui/xray-workbench-mockup.html (หน้าต้นแบบที่ผู้ใช้ตรวจแล้ว 4 รอบ) ต้นฉบับเดียวคือ design/Lab_design.md ไม่มี token ใหม่
  • ต่างจาก Worklist สองข้อเท่านั้น — (1) ค้น HN แล้ว กรองเหลือเฉพาะ order ที่มีบันทึกการใช้สารทึบอย่างน้อย 1 รายการ (2) ไม่มีปุ่มสั่งงานใด ๆ: ส่งเข้าเครื่อง · ยกเลิก order · ปฏิเสธ · ตรวจใหม่ · สร้างรายการใหม่ · หนังสือยินยอม · checkbox เลือกรายการ · dropdown Radiographer/Radiologist · สติ๊กเกอร์ HN ถูกตัดออกทั้งหมด
  • คอลัมน์แถวผู้ป่วยเหมือน Worklist ทุกช่อง — ช่องปุ่มท้ายแถวใช้บอก สารทึบ n/N และป้าย อาการ แทน ไม่ได้ปล่อยว่าง
  • ตารางในแผงรายละเอียดใช้คอลัมน์ชุดเดียวกับแท็บ order ของ Worklist: Accession No. · รายการตรวจ · เครื่อง · เวลาส่งเข้าเครื่อง · Radiographer · สถานะ · ปฏิเสธ · คนปฏิเสธ · สารทึบ · ปุ่ม ดูบันทึก · Radiographer แสดงเป็นข้อความ (ของจริงเป็น dropdown ที่เขียนค่าได้ จึงตัดออก)
  • บรรทัดสรุปบอกจำนวนใบที่ถูกซ่อนเสมอ (“ซ่อน n ใบที่ยังไม่มีบันทึก”) เพื่อไม่ให้เข้าใจผิดว่าผู้ป่วยรายนี้มีแค่ใบที่เห็น
  • ไม่มี chip กรองสถานะ (ตัดออก 2026-10-02 ตามที่ผู้ใช้สั่ง) — หน้านี้ตอบคำถามเดียวคือ “order นี้มีคนแนบใบบันทึกการใช้สารทึบไว้หรือยัง” ไม่ได้มาดูผลหรือสถานะการตรวจ · คอลัมน์สถานะยังอยู่เพราะเป็นคอลัมน์เดิมของ Worklist แต่ไม่ได้ใช้เป็นตัวกรอง
  • ⏸️ โหมด “บันทึกการใช้สารทึบ” ยังพักไว้ ตามที่ผู้ใช้สั่ง 2026-09-27 — โค้ดยังอยู่ครบ (recordForm() · dialog #recordFormDialog · ปุ่ม + บันทึก ในตาราง) เปิดกลับด้วย RECORD_MODE_ENABLED = true ที่ต้นสคริปต์ · ระหว่างนี้การบันทึกใช้ปุ่ม “สารทึบ” คอลัมน์ที่ 12 ใน X-ray CPOE Worklist ตามเดิม
  • 🔴 ไม่มีข้อมูล = “ยังไม่ได้บันทึก” เท่านั้น ห้ามอ่านว่า “ไม่ได้ฉีด” — กติกาเดิมจากคอลัมน์สารทึบใน Worklist (2026-09-23) · ใช้ทั้งกับใบที่ถูกซ่อนและรายการที่ยังว่างในใบที่แสดง
  • ของเดิมที่ใช้งานได้แล้ว ห้ามแตะ: ปุ่ม “สารทึบ” คอลัมน์ที่ 12 ของ X-ray CPOE Worklist เปิดฟอร์ม xray-contrast-media-record-v1 ผ่าน initData (item_id · accession_no · order_id · order_no · visit_id · modality · item_code · item_name) และไม่เรียก Process ใด ๆ · หน้านี้เป็น ทางเข้าเพิ่ม ไม่ใช่ของแทน
  • 🔴 ฝั่ง API ยังไม่มีทางอ่านประวัติ — xray_cpoe_worklist_api.js ยังไม่ join zdata_xray_contrast_media ⇒ ต้องเพิ่ม read path แบบ read-only ($lookup ระดับ item ผูกด้วย accession_no หรือ action ใหม่ list_contrast) ไม่งั้นตัวกรอง “เฉพาะใบที่มีบันทึก” จะไม่มีข้อมูลให้กรอง
  • ขอบเขตการค้นใช้กติกาเดียวกับ spec.md §5.1: HN แบบตรงตัว หรือ Date Range ครบสองฝั่ง · ยังไม่ระบุให้ขึ้นข้อความแนะนำและห้ามเรียก Process
  • ขอบเขตหน่วยงาน (XRAY_ORGANIZATION_CODES) ต้อง enforce ที่ server แบบ fail-closed เหมือนหน้าอื่น — dropdown เครื่องเป็นตัวกรองการแสดงผลเท่านั้น

คำถามที่ต้องเคาะก่อนลงมือ

  • 1. โหมดบันทึกจะเอากลับมาไหม — พักไว้ก่อน 2026-09-27 · ถ้าเอากลับ ต้องเป็นแบบ ค้น HN → กางใบ → เลือกรายการตรวจ เท่านั้น ไม่มีทางเลือก “บันทึกด้วย HN เปล่า” เพราะฝั่ง X-ray ยืนยันว่าบันทึกผูกกับรายการตรวจ
  • 2. 1 รายการตรวจ = 1 ใบบันทึกหรือหลายใบ — ถ้าฉีดซ้ำ/เปลี่ยนชนิดในเคสเดียวกัน ต้อง upsert ทับใบเดิม หรือเก็บหลายแถวแล้วแสดงเป็นไทม์ไลน์ (mockup นี้สมมติ 1 ใบต่อ 1 รายการตรวจ)
  • 3. ผู้บันทึกและเวลาบันทึกเก็บที่ไหน — ฟอร์มปัจจุบันไม่มีฟิลด์นี้ · ชิปใน Worklist อ่าน contrast.recorded_by/used_at ⇒ ต้องยืนยันว่ามาจาก system field ของแถว SDForm หรือให้ฟอร์มเก็บเพิ่ม
  • 4. สิทธิ์และ audit — ใครดูประวัติได้ · ใครแก้ใบที่บันทึกแล้วได้ · ต้องเก็บ log การแก้ไหม (ต่างจาก EMR sensitive result ที่มี re-auth)
  • 5. พิมพ์ใบบันทึกเป็น PDF — TOR ยังไม่ระบุ ถ้าต้องมีให้ทำผ่าน Report Factory ไม่ใช่พิมพ์จากหน้าจอ
  • 6. อาการไม่พึงประสงค์ — ต้องส่งต่อ/แจ้งเตือนที่ไหนอีกไหม (เช่น EMR, ระบบ ADR) หรือเก็บไว้ในใบนี้พอ
