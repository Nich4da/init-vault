หมายเหตุการนำไป implement

  • หน้านี้เป็น mockup ข้อมูลสมมติทั้งหมด — HN ชื่อผู้ป่วย แพทย์ เครื่อง เวลา และผลอ่าน ห้าม hard-code ลงระบบจริง
  • ระบบภาพ (สี ตัวอักษร ระยะ ขนาด component motion) ยกมาจาก 02-his/ui/lab-workbench-stock-pattern-mockup.html ทั้งชุด ต้นฉบับเดียวคือ design/Lab_design.md
  • X-ray ไม่มี specimen และ ไม่มี Lab No. — กดรับแล้วส่งเข้าเครื่องผ่าน API → Agent ได้ทันที
  • 1 accession no. = 1 order (1:1) — หน่วยของการทำงานคือ “ใบ” จึงไม่มี checkbox เลือกราย item และปุ่มใน detail เหลือ ส่งเข้าเครื่อง กับ ยกเลิก order เท่านั้น
  • Order No. มาจากใบสั่ง CPOE — รังสีเป็นฝ่ายรอรับ ไม่ได้ออกเลขเอง · รูปแบบ YYYYMMDD + running 3 หลัก เช่น 20260831011
  • Accession No. เป็นคนละเลข อยู่ ระดับ test และห้องรังสีออกเองตอนกดส่งเข้าเครื่อง · รูปแบบ YYYY MM DD + code เครื่อง + running 3 หลัก เช่น 20260831CT001 · running นับแยกตาม modality และแยกตามวัน ครบ 999 วนกลับ 001
  • ⚠️ code เครื่องที่ใช้ประกอบเลข: ยืนยันแล้วเฉพาะที่มีใน modality_type (CR CT DX IO RF UN US VCUG) ส่วน AR CTS CTA GI IVP MRI MRS PT USD USP เป็น ค่าสมมติ รอยืนยัน · และความยาวเลขไม่คงที่เพราะ code ยาว 2–4 ตัว
  • ปุ่มท้ายแถวอยู่ในคอลัมน์เดียวและเรียงต่อกันเสมอ ไม่มีช่อง – · ใบที่ยกเลิกเหลือ EMR ปุ่มเดียว
  • เหตุผลและผู้ยกเลิกแสดงเป็นคอลัมน์ ปฏิเสธ / คนปฏิเสธ ในตารางระดับ test แทน popup รายละเอียดการยกเลิกที่ถูกตัดออก
  • ปุ่ม ดูภาพ ในแท็บผลอ่านยังไม่ต่อระบบจริง — รอเชื่อมกับโปรแกรม RIS (decision X17)
  • Dropdown เครื่องกรองทันทีโดยไม่ต้องกด Search และตัวเลขบน status chip นับ ภายใต้ตัวกรองเครื่องปัจจุบัน
  • 1 order = 1 accession = 1 test — ต่างจาก LAB ที่ 1 order มีได้หลาย test ⇒ worklist หนึ่งแถวคือหนึ่งรายการตรวจ
  • ทุก test ผูกเครื่องไว้แล้วตั้งแต่ตอนสั่งใน CPOE ⇒ ไม่มีเคส “ไม่ระบุเครื่อง” ให้ UI ต้องรองรับ
  • รายการ 19 ค่าในdropdown ยัง ไม่ตรง กับ enum modality_type ใน section.json (11 ค่า, MRI vs MR) — ต้องเคาะ decision X2 ก่อนผูก master จริง
  • Agent contract ปัจจุบัน (lab_agent_order_submit_api.js) บังคับ labno และ specimen_code — X-ray ส่งผ่านตามสภาพนี้ไม่ได้ ดู decision X3 ห้ามยัดค่าปลอม
  • ขอบเขตหน่วยงานต้อง enforce ที่ server แบบ fail-closed; dropdown เครื่องเป็นตัวกรองการแสดงผลเท่านั้น ไม่ใช่ตัวให้สิทธิ์
  • “ส่งเครื่องไม่สำเร็จ” ต้องแยกจาก “ยกเลิก” และต้องไม่ rollback การรับ — ลองส่งใหม่ด้วย accession เดิมได้
