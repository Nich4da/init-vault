แสดงข้อความ raw เต็มก้อนของแต่ละการตรวจ โดยไม่ตัดหรือแปลงโครงสร้าง

เงื่อนไขการดึงค่าก่อนหน้า

ข้อเสนอสำหรับยืนยันก่อนแก้ Form/API จริง

  1. ผู้ป่วยเดียวกันค้นจาก Patient/HN เดียวกับ Order ปัจจุบันเท่านั้น
  2. รายการเดียวกันจากรหัส ไม่เทียบจากชื่อใช้รหัส Result Item/Test ที่ระบบบันทึกจริง เพื่อไม่รวมรายการชื่อคล้ายกันโดยบังเอิญ
  3. กรณีมี specimen/ตำแหน่งซ้ำMY และรายการที่รหัสเดียวกันเกิดหลาย specimen ต้องตรงทั้งรหัสรายการ + specimen + ตำแหน่งตรวจจริงก่อนนำมาเทียบ
  4. Profile / Panel เปรียบเทียบระดับผลย่อยหัว Profile ใช้จัดกลุ่มเท่านั้น แต่ละ child result ดึงประวัติจากรหัสผลย่อยของตัวเอง จึงไม่จับทั้ง Profile เป็นค่าเดียว
  5. MB เปิด Popup รายละเอียดย้อนหลังหน้าหลักแสดงปุ่มและจำนวนครั้ง เพราะผลจาก Agent เป็นข้อความ raw ก้อนยาว; Popup ซ้อนแสดงข้อความเต็ม 1–5 ครั้งโดยไม่ตัดหรือ parse ใหม่
  6. ย้อนหลังจากเวลาผลปัจจุบันเท่านั้นใช้ผลที่มี effective result time น้อยกว่าผลปัจจุบัน และตัด Order ปัจจุบันออกเสมอ
  7. สูงสุด 5 การตรวจในอดีตเรียงใหม่ไปเก่า ครั้งที่ 1–5; ถ้ามีเพียง 1–4 ครั้งแสดงเท่าที่มี ถ้าไม่มีแสดง “ยังไม่มีประวัติ”
  8. Partial / Final / Correctedนับได้เมื่อมีผลที่เผยแพร่แล้ว โดย Corrected ใช้ค่าล่าสุดที่มีผลจริงของการตรวจครั้งนั้น ไม่แยกทุก revision เป็นคนละการตรวจ
  9. ไม่นำสถานะที่ยังไม่ใช่ผลมาแสดงDraft, Pending, Order ที่ปฏิเสธ/ยกเลิก และรายการที่ถูกลบจะไม่เป็นค่าก่อนหน้า
  10. แสดง snapshot ของแต่ละครั้งค่า หน่วย การแปลผล วันเวลา และ LAB No. ต้องมาจากผลครั้งนั้น ห้ามใช้หน่วยหรือ Reference Range ปัจจุบันทับย้อนหลัง
  11. สิทธิ์และผลปกปิดยังใช้กติกาเดิมถ้าผู้ใช้ไม่มีสิทธิ์ดูผลนั้น ประวัติต้องไม่เปิดเผยค่าผ่านคอลัมน์ใหม่นี้
  12. โหลดแบบ Batch ต่อ Popupส่งรายการ matching keys ทั้งหมดครั้งเดียวและจำกัด 5 ค่า/รายการ เพื่อไม่ยิง API แยกทีละแถว
  13. ผลที่มีเฉพาะเอกสารถ้าไม่มี structured result จะแสดงประวัติเป็นการ์ดเอกสารของการตรวจครั้งนั้น ไม่สร้างค่าผลตรวจปลอมขึ้นมา
