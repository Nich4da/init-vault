## Special Widget advanced / dev only

### SD Custom Content

**DisplayUi**
**pro**
**dev only**

Render **HTML / Vue template string** อย่างปลอดภัย — รองรับ HTML tag ปกติ, component ของ Element Plus (`el-*`) + widget,
directive (`v-if` / `v-for` / `v-show` / `:` / `@`) และ interpolation `{{ varname }}` จาก prop `data` / `params`.

เทคนิค: Vue runtime compiler (lazy import) + DOMPurify sanitize + cache render function.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| content | string | '' | HTML / Vue template string ที่จะ render |
| data | object | {} | ตัวแปรสำหรับ binding — {{ name }}, v-for="i in list", v-if="ok" |
| params | object | {} | context เพิ่มเติม (override data เมื่อ key ชนกัน) เช่น params จากฟอร์ม |
| components | object | {} | widget เพิ่มเติมที่ไม่ได้ register global (el-* ไม่ต้องส่ง) |
| sanitize | boolean | true | เปิด DOMPurify sanitize (กรอง , onerror=, javascript:) |

| Method | Returns | Parameter | Description |
| --- | --- | --- | --- |
| getRef | instance \| element | name: string | เข้าถึงสิ่งที่เขียน ref="name" ใน template (widget instance หรือ DOM element) |
| getEl | HTMLElement | name: string | DOM element ของ ref — component คืน $el, tag ปกติคืน element |
| getRefs | object |  | ref ทั้งหมดเป็น object { name: ref } |
| getInner | instance |  | inner component instance (low-level เผื่อต้องเข้าถึงลึก) |

| Event | Parameters | Description |
| --- | --- | --- |
| rendered | refs: object | emit หลัง render เสร็จ + DOM mount แล้ว (ref พร้อมใช้) ส่ง refs มาด้วย |

#### 1. การใช้งานพื้นฐาน
→ `interpolation + el- + v-if`

ส่ง template เข้า `content` และตัวแปรเข้า `data` — {{ }} แสดงค่าแบบ escape เป็น text (ปลอดภัย)

*Host component:*

```js
<SDCustomContent :content="tpl" :data="vars" />

// ใน data() ของ host
tpl: `<div>
  <h3>สวัสดี {{ user.name }}</h3>
  <el-tag :type="user.vip ? 'success' : 'info'">
    {{ user.vip ? 'VIP' : 'ทั่วไป' }}
  </el-tag>
  <p v-if="user.vip">สมาชิก VIP</p>
</div>`,
vars: { user: { name: 'พี่', vip: true } }
```

#### 2. v-for แสดง array
→ `el-table / list`

วน array จาก data ด้วย v-for — เปลี่ยน array แล้ว re-render อัตโนมัติ

*Template:*

```js
<el-table :data="rows" size="small" border>
  <el-table-column prop="name" label="สินค้า" />
  <el-table-column prop="price" label="ราคา" width="120" />
</el-table>

// data
rows: [
  { name: 'ปูนซีเมนต์', price: 175 },
  { name: 'เหล็กเส้น', price: 240 },
]
```

#### 3. Event handler (@click)
→ `method ใน data`

ใส่ **ฟังก์ชัน**ใน data แล้ว template เรียกผ่าน @click / @change ได้เลย

*Template + data:*

```js
<el-button @click="greet(user.name)">ทักทาย</el-button>
<el-button @click="addItem">เพิ่ม ({{ list.length }})</el-button>

// data
{
  user: { name: 'พี่' },
  list: myReactiveList,
  greet: (name) => ElMessage.success('สวัสดี ' + name),
  addItem: () => myReactiveList.push('item'),
}

// ⚠️ inline mutation ไม่ persist: @click="counter++" เขียนกลับ data ไม่ได้
//    ต้องผ่าน method เช่น @click="inc()" โดย inc: () => data.counter++
```

#### 4. Ref helper
→ `เข้าถึง widget ภายใน`

เขียน ref="name" ใน template แล้ว host เข้าถึงผ่าน getRef — ใช้ได้หลัง render เสร็จ (ดัก @rendered หรือรอ $nextTick)

*Host:*

```js
<SDCustomContent ref="cc" :content="tpl" @rendered="onReady" />

// template มี: <el-input ref="nameInput" />

methods: {
  onReady(refs) {
    // refs = { nameInput: ElInputInstance }
  },
  focusInput() {
    this.$refs.cc.getRef('nameInput')?.focus()
    // getEl('nameInput') → DOM element
    // getRefs()          → ref ทั้งหมด
  }
}
```

#### ⚠️ Security
→ `ต้องอ่าน`

template = รัน JavaScript จริง (compile ด้วย runtime compiler) — expression เข้าถึง global ได้ (window, document, fetch)
DOMPurify กรองได้แค่โครง HTML **ไม่ได้** sandbox JS

*กฎความปลอดภัย:*

```js
// ✅ ปลอดภัย: content มาจาก dev / form schema เท่านั้น
//    (designer เขียน JS ได้อยู่แล้วผ่าน field events — trust เท่าเดิม)
// ✅ ปลอดภัย: data แสดงผ่าน {{ }} (Vue escape เป็น text เสมอ)

// ❌ ห้าม: เอา content จาก user input / URL / external API
//          → รัน JS ได้เต็มที่ (อ่าน cookie, ส่งข้อมูลออก)
// ❌ ระวัง: v-html="untrustedData" → XSS (ใช้ {{ }} แทนถ้าได้)

// กฎจำง่าย:
//   1) content รับจาก dev/schema เท่านั้น
//   2) ที่เก็บ content ต้อง write ได้เฉพาะ dev (permission guard)
```

### Vue Flow (ใน vue-ui)

**DisplayUi**
**pro**

field **vue-ui** (Components) ใช้ **@vue-flow/core** ใน template ได้โดยตรง — expose ผ่าน `vueComponents`:
`<vue-flow>`, `<Handle>`, `<Panel>`
เหมาะกับ flow diagram, workflow status, node graph

#### การใช้งานพื้นฐาน
→ `onCreated + content`

เตรียม nodes/edges ใน `vueState` ตอน onCreated แล้วผูกใน template

*vue_ui · onCreated:*

```js
const s = this.vueState
s.flowNodes = [
    { id: '1', type: 'input', position: { x: 0, y: 0 }, data: { label: 'Start' } },
    { id: '2', position: { x: 100, y: 120 }, data: { label: 'Approve' } },
    { id: '3', type: 'output', position: { x: 200, y: 240 }, data: { label: 'Done' } }
]
s.flowEdges = [
    { id: 'e1-2', source: '1', target: '2', animated: true },
    { id: 'e2-3', source: '2', target: '3' }
]
```

*vue_ui · content:*

```js
<div style="height: 400px">
  <vue-flow v-if="flowNodes" :nodes="flowNodes" :edges="flowEdges" :fit-view-on-init="true" />
</div>
```

*อัปเดตจาก field อื่น (เช่น button · onClick):*

```js
this.refField('vue_ui').vueState.flowNodes.push({
    id: '4', position: { x: 300, y: 360 }, data: { label: 'New' }
})
// reactive — กราฟอัปเดตทันที
```

#### ⚠️ ข้อควรระวัง
→ `ต้องอ่าน`

1. **container ต้องกำหนด height ชัดเจน** (เช่น `height: 400px`) — ไม่งั้น canvas สูง 0 มองไม่เห็น

2. ใส่ default ใน **onCreated** + กัน `v-if` ใน template เสมอ (กฎเดียวกับ vue-ui ทั่วไป)

3. `useVueFlow()` composable **ใช้ไม่ได้** ใน template/event — interaction ทำผ่าน props/events ของ `<vue-flow>` แทน

4. ใช้ได้เฉพาะใน field **vue-ui** เท่านั้น — SD Custom Content ที่อื่นไม่รู้จัก `<vue-flow>`

## Popup Form Guide openForm() — ง่าย → full options

เปิดอีกฟอร์มขึ้นมาเป็น dialog ด้วย `this.getFormRef().openForm(formId, dataId, parentId, initData, options)` — ไล่จากใช้งานพื้นฐานไปจนครบทุก option (ตัวอย่างใช้ form id `6a2f90e949fcdf666f694b60`)

#### Signature
→ `void`

4 อาร์กิวเมนต์แรกคือ shortcut ของ option ที่ใช้บ่อย ส่วนตัวที่ 5 (`options`) ใส่ key ที่เหลือได้ทั้งหมด

*Signature:*

```js
openForm(formId, dataId, parentId, initData, options)
//       ───────  ──────  ────────  ────────  ───────────────────────────
//       required  edit    child     prefill   { params, backdrop, readonly,
//                                                annotated, cancelCallback,
//                                                afterSaveCallback, beforeSaveCallback,
//                                                fixApiUrl, popupType, drawerDirection }
```

#### Level 1 · สร้างใหม่ → `basic`
เปิดฟอร์มเปล่าเพื่อสร้าง record ใหม่ — ใส่แค่ formId

*Example:*

```js
await this.getFormRef().openForm('6a2f90e949fcdf666f694b60')
```

#### Level 2 · แก้ไข record เดิม → `edit`
ส่ง dataId (ค่า _id ของ record) เป็นอาร์กิวเมนต์ที่ 2 → ฟอร์มจะโหลดข้อมูลขึ้นมาแก้

*Example:*

```js
const id = this.getValue()   // หรือ data.order_id
await this.getFormRef().openForm('6a2f90e949fcdf666f694b60', id)
```

#### Level 3 · pre-fill ค่าเริ่มต้น → `initData`
สร้างใหม่ (dataId = null) แต่เติมค่าตั้งต้นให้ฟอร์มผ่านอาร์กิวเมนต์ที่ 4 (initData)

*Example:*

```js
await this.getFormRef().openForm(
  '6a2f90e949fcdf666f694b60',
  null,                        // dataId = null → สร้างใหม่
  null,                        // parentId
  {                            // initData → เติมค่าลงฟอร์ม
    customer_name: data.customer_name,
    order_date: new Date(),
    status: 'draft',
  }
)
```

#### Level 4 · เปิดเป็น child → `parentId`
ผูก record ใหม่กับ record ปัจจุบันด้วย parentId (อาร์กิวเมนต์ที่ 3) — ฟอร์มปลายทางอ่านผ่าน parentId / parentData

*Example:*

```js
await this.getFormRef().openForm(
  '6a2f90e949fcdf666f694b60',
  null,
  dataId,                      // parentId = record ปัจจุบัน
  { ref_no: data.doc_no }
)
```

#### Level 5 · ส่ง params → `options.params`
ส่งค่าผ่าน `params` ในตัวที่ 5 — ต่างจาก initData ตรงที่ params เป็น read-only context (ไม่ผูกกับ field) ฟอร์มปลายทางอ่านผ่าน `formParams`

*Example:*

```js
await this.getFormRef().openForm(
  '6a2f90e949fcdf666f694b60',
  null, null, {},
  {
    params: {                  // อ่านที่ฟอร์มปลายทางผ่าน formParams
      from_form: formId,
      mode: 'review',
    },
  }
)
// ฟอร์มปลายทาง:  formParams.from_form  /  formParams.mode
```

#### Level 6 · callbacks → `before / after save`
รับ hook ก่อน/หลัง save ของฟอร์มลูก — เหมาะกับ refresh datagrid หรือคำนวณต่อหลังบันทึก

*Example:*

```js
await this.getFormRef().openForm(
  '6a2f90e949fcdf666f694b60',
  null, null, {},
  {
    // ก่อน save: รับ formData, return object ที่จะ merge เป็น initData
    beforeSaveCallback: (formData) => {
      return { created_by: userInfo.username }
    },

    // หลัง save สำเร็จ: (data = record ที่บันทึก, autoSave = boolean)
    afterSaveCallback: (data, autoSave) => {
      this.reloadOptionData('order_items')   // refresh datagrid
    },
  }
)
```

#### Full options → `ครบทุก key`
ตัวอย่างใช้ทุก option พร้อมกัน

*Example:*

```js
await this.getFormRef().openForm(
  '6a2f90e949fcdf666f694b60',  // formId  (required)
  null,                        // dataId  (null = สร้างใหม่)
  dataId,                      // parentId
  {                            // initData
    customer_name: data.customer_name,
    status: 'draft',
  },
  {                            // options (arg 5)
    params: { from_form: formId, ref_doc: data.doc_no },
    backdrop: true,            // คลิกฉากหลังเพื่อปิดได้
    readonly: false,           // เปิดแบบอ่านอย่างเดียว
    annotated: false,          // โหมด annotated
    fixApiUrl: '',             // override api url (ปกติเว้นว่าง)
    popupType: 'drawer',       // 'dialog'(default) | 'drawer' → เปิดฟอร์มเป็น drawer
    drawerDirection: 'rtl',    // ทิศ drawer: rtl/ltr/ttb/btt (เฉพาะ popupType=drawer)
    beforeSaveCallback: (formData) => ({ created_by: userInfo.username }),
    afterSaveCallback: (data, autoSave) => {
      this.reloadOptionData('order_items')
    },
    // cancelCallback: () => { ... }   // ดูข้อควรระวังด้านล่าง
  }
)
```

#### options reference → `arg 5`
key ทั้งหมดที่ใส่ใน object ตัวที่ 5 ได้

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| params | object | formParams | read-only context ส่งเข้าฟอร์มปลายทาง อ่านผ่าน formParams (ทับ params เดิมทั้งก้อน) |
| backdrop | boolean | false | คลิกฉากหลัง (close-on-click-modal) เพื่อปิด popup |
| readonly | boolean | false | เปิดฟอร์มแบบอ่านอย่างเดียว |
| annotated | boolean | false | โหมด annotated |
| beforeSaveCallback | (formData) ⇒ object | — | เรียกก่อน save, return ค่าที่ merge เป็น initData |
| afterSaveCallback | (data, autoSave) ⇒ void | — | เรียกหลัง save สำเร็จ |
| cancelCallback | () ⇒ void | subFormClose | เรียกตอนปิด/ยกเลิก — ดูข้อควรระวัง |
| fixApiUrl | string | '' | override api url ของฟอร์มปลายทาง |
| popupType | 'dialog' \| 'drawer' | 'dialog' | รูปแบบ container ตอนเปิดฟอร์ม — drawer = เปิดเป็นลิ้นชัก (พฤติกรรมเดิม = dialog) |
| drawerDirection | 'rtl' \| 'ltr' \| 'ttb' \| 'btt' | 'rtl' | ทิศของ drawer (ใช้เฉพาะ popupType = 'drawer') |

#### ⚠ ข้อควรระวัง → `gotchas`

ไม่มี width / fullscreen ใน options — ความกว้าง popup มาจาก `form_options.popup_size` ของ ฟอร์มปลายทาง (ตั้งใน builder) ไม่ได้กำหนดผ่าน openForm

cancelCallback ทับตัว default — default คือ `subFormClose` ที่ปิด popup ให้ ถ้าส่งเอง popup จะไม่ปิดอัตโนมัติ ต้องเรียกปิดเองในฟังก์ชัน

params ทับทั้งก้อน — default = formParams ของฟอร์มปัจจุบัน ถ้าส่ง params เอง ค่าเดิมจะหายทั้งหมด

openForm vs subFormOpen — `openForm` เปิดอีกฟอร์มทั้งฟอร์ม ส่วน `subFormOpen(name, rowIndex)` เปิด row ของ sub-form field ในฟอร์มเดียวกัน
