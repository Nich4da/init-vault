# X-ray RIS API — ประเด็นที่ต้องแจ้งทีม

## ✉️ ฉบับย่อ — ก๊อปส่งทีมได้เลย

> **เรื่อง: ส่งใบ X-ray เข้า Envision ไม่สำเร็จ**
>
> **อาการ** กดปุ่มส่งเข้าเครื่องแล้ว ใบสั่งบันทึกลงระบบเรียบร้อยทุกใบ
> แต่ส่งต่อไปที่ Envision ไม่สำเร็จเลยสักใบ
>
> **สิ่งที่ตรวจมาแล้ว**
> - ระบบพยายามส่งไปที่ `http://172.19.233.161/EnvisionRIE3rdParty/ThirdParty/GetOrder`
> - **ไม่มีการตอบกลับใด ๆ เลย** — ไม่ใช่ถูกปฏิเสธ แต่คือติดต่อไม่ได้ตั้งแต่แรก
> - ทดสอบยิงจากคอมในโรงพยาบาล → Envision ตอบปกติ **แปลว่าตัวเครื่อง RIS ทำงานอยู่**
> - แต่ระบบ HIS อยู่บนคลาวด์ (`apihis.softmax-one.com`) ส่วน `172.19.x.x` เป็นเลขเครือข่ายภายในโรงพยาบาล
>
> **คำถามหลัก (ต้องแก้ก่อน ไม่งั้นไปต่อไม่ได้)**
> 1. เซิร์ฟเวอร์ HIS ที่อยู่บนคลาวด์ ติดต่อเข้ามาหาเครื่อง RIS ในโรงพยาบาลได้จริงไหม
>    รบกวน **ทดสอบจากเครื่อง HIS เอง** ไม่ใช่จากคอมในโรงพยาบาล
> 2. ถ้าติดต่อไม่ได้ ต้องเปิดทางเชื่อม (VPN) หรือย้าย Envision ไปใช้ที่อยู่ที่คลาวด์เข้าถึงได้
>
> **คำถามถัดไป (เจอแน่หลังเชื่อมต่อได้)**
> 3. Envision ต้องใส่รหัส/กุญแจยืนยันตัวตนไหม — ตอนนี้ระบบส่งไปเปล่า ๆ
>    และตอนทดสอบ Envision ตอบกลับว่า **"ไม่ได้รับอนุญาต" (401)**
> 4. ใบสั่งที่เพิ่งสร้างใหม่ ควรส่งสถานะเป็น **N (คำขอ)** หรือ **A (มาถึงเครื่องแล้ว)**
>    ตอนนี้ฝั่งเราส่ง A ทุกใบ ถ้าควรเป็น N บอกได้ เราแก้ให้ทันที
> 5. ต้องส่ง **รหัสเครื่อง (ModalityUid)** ไปด้วยไหม — ถ้าต้อง **ขอรายชื่อรหัสเครื่องทั้งหมด**
>    เพราะฝั่ง HIS ไม่มีข้อมูลนี้เลย มีแต่ชนิดเครื่อง (CT / DX)
> 6. ขอ **เอกสารสเปคของ Order** ด้วย — ที่ได้มาเป็นของ Schedule
>
> **จุดที่อยากให้ทีมแก้ในโค้ด**
> 7. ตอนส่งเลข Accession ต่อไป Envision ระบบไม่ได้ตัดช่องว่างหน้า-หลังออกก่อน
>    ทำให้เลขที่เก็บใน HIS กับที่ส่งไป Envision อาจไม่ตรงกัน

---


ตรวจจากไฟล์เวอร์ชันล่าสุด (อัปเดต 2026-09-09 16:07–16:08) และข้อมูลจริงใน MongoDB
**อ่านป้าย 🛠 ของแต่ละข้อก่อน** — บางข้อทีมต้องแก้โค้ด บางข้อแค่ต้องการคำตอบแล้ว HIS แก้เอง

> เรื่องผลอ่าน (result / result reset) และใบนัด (schedule) ย้ายไปส่วน B ไว้คุยรอบหน้า

|---|---|---|
| **A0 HIS ต่อ Envision ไม่ได้** | **ทีม/IT** | เปิดเส้นทางจาก HIS cloud → `172.19.233.161` |
| A0b Envision ตอบ 401 | **ทีม** | ใส่ auth ให้ `xray_api_order.js` (เจอหลังเปิด network) |
| A1 `Status` `N`/`A` | **HIS** | ตอบว่าค่าไหนถูก |

## 🔴 A0. เซิร์ฟเวอร์ HIS **ต่อไปหา Envision ไม่ได้เลย**  🛠 **ทีม/IT ต้องเปิดเส้นทาง**

**พิสูจน์แล้วจาก runtime 2026-09-09 18:09** — หลัง deploy โค้ดที่เก็บเหตุผลจริง ระบบบันทึกไว้ว่า

```json
"forward_error": "ECONNABORTED",
"forward_http_status": null,
"forward_response": "",
"local_saved": true
```

`forward_http_status: null` แปลว่า **ไม่เคยได้ response กลับมาเลยแม้แต่ status เดียว**
ไม่ใช่ถูกปฏิเสธ — คือ **ต่อไม่ติดตั้งแต่แรก** (`ECONNABORTED` = การเชื่อมต่อถูกยกเลิก/หมดเวลา)

สาเหตุที่น่าจะเป็น: `ORDER_FORWARD_URL` ชี้ไป **`172.19.233.161` ซึ่งเป็น private IP ในวง LAN
โรงพยาบาล** แต่ Process รันอยู่บน **เซิร์ฟเวอร์ HIS ที่เป็น cloud** (`apihis.softmax-one.com`
· Cloudflare) ⇒ ปกติ cloud จะ route ไปหา 172.19.x.x ไม่ได้ ถ้าไม่มี VPN / site-to-site tunnel

**ขอให้ทีม/IT**
1. ยืนยันว่าเซิร์ฟเวอร์ HIS มีเส้นทางไปหา `172.19.233.161:80` จริงไหม (ping / telnet จากเครื่อง HIS เอง)
2. ถ้าไม่มี — เปิด VPN/tunnel หรือย้าย Envision มาอยู่บน address ที่ HIS เข้าถึงได้
3. ระหว่างนี้ถ้าจะทดสอบ ให้ deploy `xray_api_order` ตัวที่ยิงจากเครื่องในวง LAN แทน

> ยืนยันว่า Envision เองยังทำงานปกติ — ยิงจากเครื่องในวง LAN โรงพยาบาลได้
> `GET` → `405 Method Not Allowed` · `POST` → `401 Unauthorized` (IIS/ASP.NET)
> ⇒ endpoint มีชีวิต รับ POST แต่ HIS ไปไม่ถึง

## 🟠 A0b. Envision ตอบ **401 Unauthorized** — `xray_api_order` ไม่ได้ส่ง auth  🛠 **ทีมต้องแก้โค้ด**

**ยังไม่ใช่ตัวบล็อกตอนนี้** (ตัวบล็อกคือ A0) แต่จะเจอทันทีที่เปิด network ได้

**พบจากการทดสอบจริง 2026-09-09 17:30** — HIS ส่งใบสั่ง 3 ใบผ่าน `app.runProcess`
บันทึกลง `zdata_xray_order` สำเร็จครบทั้ง 3 (`SM20260909CT001` `DX001` `DX002`)
แต่ทั้ง 3 ใบได้ `AE` กลับมาว่า **"Order saved locally, but forwarding failed"**

ยิงตรงเข้า endpoint จากเครื่องในวง LAN โรงพยาบาลเพื่อหาสาเหตุ:

```
GET  http://172.19.233.161/EnvisionRIE3rdParty/ThirdParty/GetOrder   → 405 Method Not Allowed
POST (Content-Type: application/json, body {})                        → 401 Unauthorized
     Server: Microsoft-IIS/10.0 · X-AspNet-Version: 4.0.30319
```

⇒ **endpoint มีชีวิตและรับ POST แต่ต้องมี authentication** ส่วน `xray_api_order.js` บรรทัด 140–141
ส่งแค่ header เดียว:

```js
const forwarded = await app.axios.post(ORDER_FORWARD_URL, forwardInput, {
  headers: { 'Content-Type': 'application/json' },   // ← ไม่มี auth เลย
```

**ขอให้ทีม**
1. ยืนยันว่า Envision ต้องใช้ auth แบบไหน (Basic · Bearer · API key header · Windows/NTLM)
2. ใส่ credential ให้ `xray_api_order.js` — เก็บฝั่ง API Factory ไม่ต้องส่งมาให้ HIS
3. เช็คด้วยว่า **เซิร์ฟเวอร์ HIS (cloud) route ไปหา `172.19.233.161` ซึ่งเป็น private IP ได้จริงไหม**
   ทดสอบข้างบนยิงจากเครื่องในวง LAN ไม่ใช่จากเซิร์ฟเวอร์ HIS ⇒ ยังพิสูจน์ไม่ได้ว่า HIS ถึง

> แยกสองปัญหานี้ออกจากกันได้ทันทีถ้า `xray_api_order` ส่ง `ForwardHttpStatus` / `ForwardError`
> กลับมาให้เห็น — ได้ `401` แปลว่าถึงแต่ auth ไม่ผ่าน · ได้ `ETIMEDOUT`/`ECONNREFUSED`
> แปลว่า route ไปไม่ถึงเลย (ตอนนี้ค่าเหล่านี้ถูกส่งกลับมาแล้วแต่ฝั่ง HIS ยังไม่ได้เก็บ)

## 🔴 A1. ใบสั่งที่เพิ่งสร้าง ควรส่ง `Status` เป็น `N` หรือ `A`  🛠 HIS แก้เอง · ขอแค่คำตอบ

ตอนนี้ HIS ส่ง **`Status: 'A'` ตายตัวทุกใบ** ตอนกดปุ่ม "ส่งเข้าเครื่อง"
(hardcode อยู่ที่ `xray_cpoe_dispatch_api.js:233` ซึ่งเป็นไฟล์ฝั่ง HIS — **ไม่ใช่โค้ดของทีม**)

แต่เอกสารสัญญาระบุว่า

```
Order Status:  N = Request   ·   A = Arrival (default)
```

⇒ ถ้า `A` แปลว่า "ผู้ป่วยมาถึงเครื่องแล้ว" การส่ง `A` ตั้งแต่ตอนสั่ง
**อาจทำให้ RIS เข้าใจว่าคนไข้ยืนอยู่หน้าเครื่องแล้วทั้งที่ยังไม่มา**

ข้อมูลจริงใน `zdata_xray_order` มีทั้งสามค่า: `A` 10 แถว · `N` 2 แถว · `C` 2 แถว
โดยที่ `N` มาจากแถวที่ทีม seed ไว้ ⇒ ดูเหมือน `N` คือค่าที่ถูกสำหรับใบใหม่

**ขอคำตอบ:** ใบสั่งใหม่ต้องเป็น `N` หรือ `A` และ RIS ใช้ค่านี้ทำอะไรต่อ
(ถ้าเป็น `N` ฝั่ง HIS แก้เองได้ทันที เป็นการแก้ไฟล์ของเรา)

## 🟡 A2. `ModalityUid` — Order บังคับไหม และขอรายการรหัสเครื่อง  🛠 HIS แก้เอง · ขอข้อมูล

ข้อมูลจริงของทีมใน `zdata_xray_order` มี `ModalityUid` **12 จาก 14 แถว**

```
ModalityUid     = "XR01"    ModalityName     = "Digital Radiography"   ← ตัวเครื่อง
ModalityTypeUid = "XR"      ModalityTypeName = "X-Ray"                 ← ชนิดเครื่อง
```

HIS ส่งได้แค่ `ModalityTypeUid` = `CT` / `DX` (ชนิด) เพราะ **ไม่มีรหัสเครื่องของ RIS อยู่เลย**
ตรวจครบแล้วทุกที่: `zdata_ris_radio_exam` (1,825 รายการ) · `zdata_ris_group` ·
`zdata_section` · `zdata_room`

**ขอ 2 อย่าง**
1. Order **บังคับ** `ModalityUid` ไหม (ใน PDF ติด `*` เฉพาะฝั่ง Schedule)
2. ถ้าบังคับ ขอ **รายการรหัสเครื่องทั้งหมดของ RIS** เพื่อ map จากห้องของ HIS
   (`X2` `X3` `X11` `US1` `US2` `RF` `CT` `MRI`) ไปเป็นรหัสของ RIS

## 🟠 A3. `xray_api_order` ส่ง `AccessionNo` ที่ยังไม่ trim ต่อไป Envision  🛠 **ทีมต้องแก้โค้ด**

**ไฟล์:** `xray_api_order.js` บรรทัด 45–49

```js
const forwardInput = { ...input };                       // ← copy ก่อน
input = { ...input };
input.AccessionNo = String(input.AccessionNo).trim();    // ← trim เฉพาะ input
```

`forwardInput` ถูก snapshot **ก่อน** trim ⇒ ถ้า caller ส่ง `" ACC123 "` มา
**HIS เก็บ `ACC123` แต่ Envision ได้ `" ACC123 "`** สองระบบจะ match กันไม่เจอถาวร

**ขอให้:** ย้าย copy ไปหลัง trim หรือ trim ทั้งสองตัว
(ฝั่ง HIS trim ให้อยู่แล้วจึงยังไม่เจอ แต่ caller อื่นไม่ปลอดภัย)

## 🟡 A4. ขอสเปกหน้า **Order** (ตอนนี้มีแต่หน้า Schedule)  🛠 ขอเอกสาร

เอกสารที่ได้รับเป็นตาราง `Service Name: Schedule` ⇒ **ยังไม่มีหน้าสเปกของ Order**

จึงยังไม่รู้ว่า Envision บังคับฟิลด์ไหนบ้างสำหรับ Order เพราะ `xray_api_order.js`
บังคับแค่ `AccessionNo` แล้ว forward ทั้งก้อนต่อ ⇒ **ตัวตัดสินจริงคือ Envision ซึ่งอ่านโค้ดไม่ได้**

ปัจจุบัน HIS ส่ง 14 ฟิลด์เสมอ + optional อีกไม่เกิน 15 ฟิลด์เฉพาะที่มีค่า
(รายละเอียดอยู่ใน `spec.md` §0.2) **ขอหน้าสเปก Order เพื่อยืนยันว่าครบหรือขาด**

# ส่วน B — เก็บไว้รอบหน้า (ยังไม่ต้องตอบตอนนี้)

บันทึกไว้ไม่ให้หาย แต่ไม่เกี่ยวกับการทำให้ "ส่งได้ถูกต้อง"

- **B1 `xray-api-ris-result` แทรกแถวใหม่ทุกครั้ง** (บรรทัด 95–98 `dbInsert` เสมอ)
  RIS ยิงซ้ำ/ผลอ่านฉบับแก้ ⇒ หลายแถวต่อ accession โดยไม่มี flag บอกฉบับล่าสุด
  และไม่เช็คว่า accession มีใบสั่งจริง
- **B2 `xray_resultreset` อาจ reset ผิดแถว** — `sdformGetOne` โดยไม่มี `ORDER BY`
  ประกอบกับ B1 ที่ทำให้มีหลายแถว ⇒ อาจตั้ง `Status='C'` ทับฉบับเก่า
- **B3 สเปก Schedule ไม่ตรงโค้ด** — PDF ให้ `AdmissionNo`/`PatientSsn` บังคับแต่โค้ดตัดออก
  และ PDF ไม่มี `AccessionNo` เลย ใช้ `ScheduleUid` เป็นเลขใบนัด ขณะที่โค้ด upsert ด้วย `AccessionNo`

## 🔴 A5. ผลอ่านแยกเป็นสองตารางแล้วโดยไม่ได้แจ้ง — และ `xray_resultreset` ชี้ผิดฟอร์ม  🛠 **ทีมต้องยืนยัน/แก้**

ตรวจ `sdform_manage` แบบ read-only 2026-09-16 พบว่าเมื่อ **2026-09-09 22:45–23:11** มีการ:

| Form ID | ชื่อใหม่ | ตาราง | บทบาท |
|---|---|---|---|
| `6a860980f851000f28e44ab0` (ของเดิม) | `xray_result_log` | `zdata_zdata_xray_result_log` | เก็บ**ทุกข้อความ**ที่ยิงเข้ามา + `ResultId` |
| `6aa180f009c1bad08952da58` (สร้างใหม่) | `xray_result` | `zdata_xray_result` | **ฉบับปัจจุบัน** upsert ทับต่อ 1 Accession |

หลักฐานจากข้อมูลจริง: `SM20260910DX001` ยิงเข้ามา 6 ครั้ง (14/09) → log 6 แถว · result 1 แถวที่ถูกทับ ·
`SM20260910DX003` ยิงซ้ำ 15/09 20:17 → log แถวใหม่ · result แถวเดิมถูก `updated_at` ทับ

**คำถาม/สิ่งที่ต้องการ**

1. ยืนยันว่า `zdata_zdata_xray_result_log` เป็น **log ถาวรที่อ้างอิงได้** ไม่ใช่ที่พักชั่วคราวที่จะถูกล้าง
   (HIS จะอ่านตารางนี้เป็น "ประวัติการแก้ผลอ่าน" ให้เจ้าหน้าที่ดู)
2. ขอ **JSON ของฟอร์ม `xray_result` ตัวใหม่** (`6aa180f009c1bad08952da58`) มาเก็บในรีโป
   — ตอนนี้เรามีแต่สำเนาของฟอร์มเดิมที่กลายเป็น log ไปแล้ว
3. **`xray_resultreset.js` ตั้ง `RESULT_FORM_ID = '6a860980f851000f28e44ab0'`** ซึ่งตอนนี้คือฟอร์ม **log**
   แต่โค้ดสั่ง `dbUpdate` ลงตาราง `zdata_xray_result` ⇒ ได้ `_id` มาจากคนละคอลเลกชัน
   **เส้นทางถอนผลจึงหาแถวไม่เจอ/อัปเดตไม่โดน** — ต้องเปลี่ยนเป็น `6aa180f009c1bad08952da58`
4. เอกสารที่ทีมเคยให้ (และคอมเมนต์ในโค้ดเอง) ระบุว่า *"Every valid request inserts a new result · Never update"*
